# deploy.sh 交互式选择 cron 执行周期 — 设计文档

- 日期: 2026-07-26
- 状态: 已批准，待 spec 审查
- 关联: 上轮清理 `config.json` 死配置（方案 B，已落地）

## 背景

`deploy.sh` 的 `create_cron_job()` 当前在 `deploy.sh:302` 硬编码 `cron_expr="*/10 9-18 * * 1-5"`，install 过程既不询问用户、也不让用户自定义执行周期。`config_wizard` 是「步骤 1/1」，只配 API Key。第 222 行残留注释 `# 交互式输入时间` 显示「原计划做交互式输入时间但未实现」。

用户希望在 install 时能交互选择 cron 执行周期，并把默认时段从 9–18 扩到全天。

## 目标

1. install 时交互式选择 cron 执行周期（预设菜单 + 自定义兜底）。
2. 默认周期改为 `*/10 0-23 * * *`（每天 0:00–23:59，每 10 分钟）。
3. README 只推「下载后直接执行」，并更新与新功能匹配的描述。
4. 恪守方案 B：cron 周期**不写入 `config.json`**，只在 install 时决定、写进 crontab。

## 非目标

- 不让 `config.json` 控制 cron（上轮已清理死配置）。
- 不为管道模式新增 `CRON_EXPR` 等环境变量。

## 设计

### 调用顺序

`install_service` → `config_wizard`（步骤 1 API Key → **步骤 2 选周期**）→ `create_cron_job`（用所选周期生成 cron）→ `test_run`。

### 新增函数 `input_cron_schedule`

- 位置：`input_api_key` 附近。
- 回传：全局变量 `SELECTED_CRON_EXPR`（与 `input_api_key` 用 `RETURN_VALUE` 风格一致）。
- 交互形态：`echo` 编号列表 + `read -p "请输入序号 [1]: "`，**支持回车 = 默认**。
- 预设清单：
  1. `*/10 0-23 * * *` — 每天 0:00–23:59，每 10 分钟（默认）
  2. `*/30 0-23 * * *` — 每天 0:00–23:59，每 30 分钟
  3. `*/10 0-23 * * 1-5` — 工作日 0:00–23:59，每 10 分钟
  4. `*/30 9-18 * * 1-5` — 工作日 9–18 点，每 30 分钟
  5. 自定义（手动输入 cron 表达式）
- 自定义分支：再 `read` 一个表达式，做**轻量校验**——按空格切分必须 5 段、每段仅含 `0-9 * / - ,`；不合法提示重输。
- 非法序号：提示重输。

### 非交互 / 管道模式

`input_cron_schedule` 开头检测 `[ ! -t 0 ]`（stdin 非 tty），若是则 `SELECTED_CRON_EXPR="*/10 0-23 * * *"; return`，不弹菜单——与现有 `ZHIPU_API_KEY` 管道流程一致，不引入新环境变量。

### 串接改动

- `config_wizard`（`deploy.sh:247`）：步骤编号 `1/1` → `1/2 配置 API Key` + `2/2 选择执行周期`，调用 `input_cron_schedule`。
- `create_cron_job` 第 302 行：`local cron_expr="${SELECTED_CRON_EXPR:-*/10 0-23 * * *}"`（优先用所选，兜底默认）。
- 文案更新：第 272（配置摘要）、299、326 行的「工作日 9:00-18:00，每10分钟」替换为实际所选周期的描述。

## 验证

- **交互模式**：`./deploy.sh install`，验证菜单显示、回车默认、各预设正确映射、自定义合法/非法输入处理。
- **管道模式**：`bash deploy.sh install < /dev/null`（或设 `ZHIPU_API_KEY`）验证直接用默认、不卡在读输入。
- **校验**：自定义输入 `* * *`（3 段）、`abc`（非法字符）应提示重输。
- **注意**：`test_run` 会真实调用智谱 API 消耗额度；验证 cron 逻辑时应跳过 `test_run` 或用无效 key 让其在额度查询阶段安全失败。
